### The v8 bump (v7.3.20..v8.0.3, 15 commits)

Module path `/v7` to `/v8` across 912 files (import-line only), a v8
configuration tree (`internal/config/config_v8.go`) with a layout migration,
a v8 management API (`server_management_v8.go`, `config_v8.go` handler,
`auth_files_v8.go` with query-param OAuth routes), an `APIKeyConfigExecutor`
that hands API-key credentials a config view stripped of OAuth-only
settings, and discovery bonded-interface support. The migration is the
only behaviour that reaches this fork's operation:

- On load (`LoadConfigOptional`), `NormalizeConfigLayout(data, migrate=false)`
  removes a *legacy* field only when its *v8* counterpart is also present. A
  legacy-only `config.yaml` like the seat's is left untouched on load.
- On a v8 management write (`migrate=true`), every legacy field is moved to
  its v8 path and **every top-level section not in `v8AllowedRoots()` is
  commented out**. The fork's `egress`, `usage-cache-stats` and `claude-code`
  sections are not in that table.

### Lockdown gaps (closed on this rebase)

1. The v8 migration would comment out `egress:` on a panel-driven config
   save, which would silently drop the allowlist to its defaults on the next
   reload. Closed by registering the fork's three sections (`egress`,
   `usage-cache-stats`, `claude-code`) in the v8 path table so they are
   preserved, plus a test that runs `NormalizeConfigLayout(.., true)` over a
   config carrying them and asserts they survive uncommented.
2. `oauth_scope_executor.go` adds `ForAPIKey()` on every executor by value
   receiver. The Claude executor's keepalive and cache-stats hooks read
   `e.cfg`; the copy keeps the same pointer stores, so nothing detaches, but
   the carried keepalive commit must compile against the new method set.
   Verified by `make verify` after the rebase.
